## BLOCKERS

1. **Stored session switches are not refreshed at the child run boundary.** `modules/subagent-context/index.ts:376-382` gates injection on cached `entry.runtime.enabled`; it never calls the live refresh. `extensions/coworkflow.ts:283-293` implements refresh but no `before_agent_start` listener invokes it (despite the “every agent turn” comment). A child started while its parent's stored flag is on continues injecting after that parent turns off; a child started with the flag off also cannot begin injecting just because that flag is later enabled. Reproduced through the actual extension factory and registered hooks, in a temporary project: start child with stored parent flag true → first hook injects → `setSessionFlag(root, "parent", false)` → next `before_agent_start` with fresh structured options still injects. Actual output: `{"probe":"stored parent off -> next child turn","childBlockStillInjected":true,"loadState":"child"}`. This violates PRD acceptance 3 and the required live session/module behavior. Repair should refresh at the production run boundary before dependent child hooks; regression must change the persisted flag, rather than directly mutating a fake runtime's `enabled`.

2. **Turning on a module that was initially off does not register its feature command in an already loaded session.** `extensions/coworkflow.ts:753-765` calls `ensureRuntime()` and `notifyRuntimeChange()` after `setSwitch`, but never `activateSession()`. `subagentsModule.activate` registers observers/resources; `/Coworkflow:run` is registered only by `onSessionActivate`. `refreshSession` invokes that activation only on the whole layer's disabled→enabled transition. Reproduced through the actual extension factory/control surface, in a temporary adopted project with `autoEnable:true` and subagents initially false: `session_start` → `controlSurface().setSwitch("subagents", true)` → await `subagentsRuntimeSettled(host)`. The control returns `subagents → on（本会话已生效）`, but the host command map still has no `Coworkflow:run`. The same activation ordering affects initially disabled lane commands. This violates same-session module reenable without restart. Reconcile command activation after newly attaching enabled modules; cover initially-off→on, not only off→on of commands already registered.

Both probes passed their assertions that the defects are present. No fixes or repository tests were added.
